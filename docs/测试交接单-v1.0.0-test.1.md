## 5. 测试范围

### 本轮测试

**一、用户注册**

1. 正常注册：用户名 + 密码合法 → 注册成功
2. 用户名校验：为空、纯空格、超过 30 位
3. 密码校验：为空、少于 6 位
4. 重复用户名注册被拒绝（含快速双击提交的并发场景）
5. 用户名首尾空格被自动去除（`" alice "` 与 `"alice"` 视为同一账号）
6. 传入非字符串类型（如数组、数字）时不崩溃，返回明确错误
7. 注册后数据库中存储的是密码哈希，而非明文

**二、用户登录**

1. 用户名密码正确 → 返回 `access_token`
2. 密码错误 → 拒绝
3. 用户名不存在 → 拒绝
4. 用户名首尾空格被自动去除
5. 请求体为空或非 JSON 时的错误提示

**三、JWT 令牌**

1. 令牌有效期为 2 小时
2. 令牌可被解码，payload 含 `username` 与 `exp`
3. 伪造令牌被拒绝（用其它密钥签发的令牌）
4. 篡改令牌内容后被拒绝
5. 过期令牌被拒绝

**四、前端登录态与路由**

1. 未登录访问受保护页面 → 跳转登录页
2. 已登录访问登录页 / 注册页 → 跳转首页
3. 刷新页面后登录态保持
4. 退出登录后令牌被清除
5. 收到 401 响应时自动清除令牌并跳转登录页

**五、访问链路**

1. 前后端通过同一域名访问（无跨域问题）
2. 静态资源加载正常、刷新子页面不 404

### 本轮不测试

- 管理员 / 角色 / 权限体系（本版本未实现）
- 找回密码、修改密码（未实现）
- 第三方登录（微信 / GitHub 等）、邮箱或短信验证码（未实现）
- 用户注销、账号删除、注销账号后的数据处理（未实现）
- HTTPS / 证书安全（测试环境为明文 HTTP）
- 性能与压力测试（测试环境为单机、gunicorn 单 worker + 4 线程、SQLite 单文件写锁，**不代表生产容量**）
- 移动端适配与多浏览器兼容性（尚无正式兼容性声明）
- 服务器运维、部署流水线本身的正确性（由开发自测）

# 附录 A：接口清单

### POST `/api/register` —— 用户注册

请求体：

```json
{ "username": "alice", "password": "secret123" }
```

| HTTP | 返回 message | 触发条件 |
| --- | --- | --- |
| 200 | 注册成功 | 注册成功 |
| 400 | 请求内容不能为空，请传入JSON数据 | 请求体不是合法 JSON |
| 400 | 用户名和密码格式不正确 | 传入的不是字符串 |
| 400 | 用户名不能为空 | 用户名为空或纯空格 |
| 400 | 密码不能为空 | 密码为空 |
| 400 | 密码长度不能少于 6 位 | 密码少于 6 位 |
| 400 | 用户名长度不能超过 30 位 | 用户名超过 30 位 |
| 400 | 该用户名已被注册 | 用户名重复 |
| 500 | 注册失败，请稍后重试 | 数据库异常 |

### POST `/api/login` —— 用户登录

请求体：

```json
{ "username": "alice", "password": "secret123" }
```

成功返回：

```json
{ "message": "登录成功", "code": 200, "access_token": "<JWT 字符串>" }
```

| HTTP | 返回 message | 触发条件 |
| --- | --- | --- |
| 200 | 登录成功 | 校验通过 |
| 400 | 请求内容不能为空，请传入JSON数据 | 请求体不是合法 JSON |
| 400 | 用户名和密码格式不正确 | 传入的不是字符串 |
| 400 | 登录失败 | 用户名不存在或密码错误 |

> 注意：账号不存在与密码错误返回**同一个提示**（登录失败），这是刻意的，避免被人枚举出哪些用户名已注册。

### GET `/api/user/profile` —— 获取当前用户信息（受保护）

请求头：

```
Authorization: Bearer <access_token>
```

| HTTP | 返回 message | 触发条件 |
| --- | --- | --- |
| 200 | 成功获取 xxx 的个人信息 | 令牌合法 |
| 401 | 缺少有效通行证 | 未带 token 或格式不是 `Bearer xxx` |
| 401 | 通行证已过期 | 令牌超过 2 小时 |
| 401 | 无效的通行证 | 令牌被篡改、伪造或密钥不匹配 |

# 附录 B：已知限制与注意事项

| # | 限制 | 对测试的影响 |
| --- | --- | --- |
| 1 | 明文 HTTP，无 HTTPS | 不要在测试环境输入真实敏感密码 |
| 2 | 无预置账号 | 必须先自行注册才能测试登录 |
| 3 | 数据不持久 | 每次部署后账号全部消失，需重新注册；请勿把重要测试数据只留在这里 |
| 4 | 令牌有效期仅 2 小时且不可续期 | 长时间测试需重新登录，属预期行为 |
| 5 | 单 worker 架构 | 并发压力测试结果无参考价值，**不要做压测** |
| 6 | 无密码强度校验 | 只校验长度 ≥ 6，如「123456」也能注册成功；这属于本版本的已知取舍，不是 Bug |
| 7 | 无登录失败次数限制 | 可以无限次尝试密码。安全加固（限流、锁定）不在本版本范围内，**不要作为 Bug 提交** |
| 8 | 账号不存在与密码错误提示相同 | 设计如此，便于防止用户名枚举 |
| 9 | 版本自动更新 | 推送 `test` 分支即自动部署，测试期间务必冻结该分支 |
